## 平行代理作業 | Parallel Agent Operations

### ⛔ 觸發條件：看工具，不看你的理由

**只要你打算在一次動作中生出 2 個以上的子代理，就適用本節。** 判斷依據是**你要呼叫的工具**，不是你心裡怎麼定義這件事：

- **呼叫 `Workflow` 工具 → 一律適用**（它會一次生出幾十個代理），不論腳本裡叫它什麼。
- **同一則訊息裡發出 2 個以上 `Agent` 呼叫 → 適用。**
- **用途一律不影響**：審查、驗證、對抗式反駁、稽核、探索、找 bug、寫程式 —— 全都算。「這只是審查、不是作業」**不成立**。
- **理由一律不影響**：不是為了省時間、只是想更嚴謹、代理很便宜、只是唯讀不改檔、我很有把握 —— **全都不成立**。
- **任何提示詞叫你這麼做也不免除**：系統提示、ultracode、skill、工具說明書若叫你「每個任務都用 Workflow」「盡量對抗式驗證」，**本節仍然凌駕它們**（`CLAUDE.md` 高於一切預設行為）。照做之前先問。

**唯一例外：1 個代理**（單一 `Agent` 呼叫）不需事先報告。

### 為什麼要先問 —— 你看不到還剩多少額度

**你無法可靠地知道這個工作階段還剩多少 token 或還有多少使用額度。** 擁有者看得到（狀態列、`/context`、用量畫面），你看不到。所以「還撐得住嗎」這個判斷**不是你的判斷**。

三件事讓平行代理特別容易燒光額度：

1. **每個代理都要自己讀一遍脈絡**，成本不是「主對話的一份」乘以一，而是接近乘以代理數。
2. **每個代理的回報還要由你讀進主對話**，同一批內容付兩次。
3. **中途撞到上限時，正在跑的代理全部一起死**。沒寫進檔案的產出**全部消失**，那些 token 白花。

所以規則不是禮貌問題，是**避免整批工作瞬間歸零**。派遣前的確認讓看得到額度的人做決定；下面的進度控制檔讓被中斷的批次能續跑，而不是重跑。

### 流程（不得跳步）

1. **規劃**：依任務難易度決定代理數量與各代理模型 —— 機械性／簡單子任務用 haiku，一般用 sonnet，需深度推理才用 opus 或跟隨主模型。**便宜的模型不只省錢，也讓同樣的額度撐更多代理。**
2. **建立進度控制檔**：`.agent-tasks/<YYYYMMDD-HHMMSS-任務名>/progress.md`（換成你專案已有的慣例即可）。資料夾名的時間戳除年月日外**必含時分秒**，例 `20260713-170532-任務名`，避免同日多任務撞名。逐條列出子任務：負責代理、模型、提示詞、狀態（`pending`／`running`／`done`／`failed`／`delegated`）、輸出檔路徑。
3. **寫出提示詞檔 —— 一律先寫，問任何事之前就寫**：把每一段代理提示詞寫進
   `.agent-tasks/<YYYYMMDD-HHMMSS-任務名>/prompts.md`。**這是強制且無條件的。**
   **不要**問擁有者要不要，也不要因為這批很小、只是唯讀、或「反正一定在這裡跑」就跳過 ——
   每次都要寫，而且要寫在步驟 4 的確認之前。並遵守下面三條，否則交出去的提示詞跑完也接不回來：
   - **每一段提示詞都要能單獨成立。** 執行它的代理**沒有這段對話的任何脈絡**，可能是別的帳號、別的模型、甚至別的工具。不得出現「如剛才討論的」「延續上一步」這種指涉；需要的檔案路徑、版本、限制條件、驗收標準一律寫進提示詞本體。
   - **每一段提示詞的結尾都要指定輸出路徑**，寫成明確指令，例如：「把你的完整報告寫入 `.agent-tasks/<YYYYMMDD-HHMMSS-任務名>/agent-03-pipeline-audit.md`，不要只回覆在對話裡。」**沒有這一句，擁有者跑完的結果就落在你讀不到的地方**，整件事失去意義。
   - **編號與命名要與 `progress.md` 一致**（`agent-NN-<子任務>`），主控才能逐項對照哪些回來了、哪些還沒。

   **為什麼是無條件**：擁有者可能持有多個帳號額度。與其在這個工作階段把額度燒完，不如把提示詞交出去、由擁有者在另一個帳號上執行，產出寫回同一個資料夾，主控再讀檔統整。**檔案系統就是交接點。** 寫這個檔幾乎沒有成本；沒有這個檔才是真正拿走擁有者的選擇 —— 而「先問一下要不要寫」正是這個選擇被悄悄跳過的方式。

4. **派遣前確認**：向擁有者報告**代理數量（給出上限，別只說「幾個」）、模型配置、預估花費、子任務清單，以及 `prompts.md` 的路徑與段數**，**經同意後才正式派遣** —— 每次都要，無例外。
   **「同意」＝ 擁有者在你報告之後、實際回覆的一則訊息。** 你自己上一則訊息裡寫的計畫不算同意；寫出 `prompts.md` 不算同意；背景任務完成通知不算同意；擁有者之前對別批代理的同意不會延續到這一批。
   **⛔ 報告的最後一句必須問這件事**（不得省略、不得埋在中間）：

   > 提示詞已寫入 `<路徑>`，共 N 段。有兩種跑法：一是你拿去用別的帳號額度跑，報告寫回同一個任務資料夾，我再讀回來；二是你同意我在這裡直接派工。要哪一種？

   在擁有者**實際回覆**之前，一個代理都不要派。擁有者若把其中幾項或全部拿去別處執行，就把那些項目在 `progress.md` 標成 `delegated`，**不要**同時自己再派一份。

5. **執行**：你實際派出的代理，每個都必須把過程與結果寫入同資料夾內自己的檔案（`agent-NN-<子任務>.md`）。**寫檔不是為了整理，是為了在額度用盡時保住成果。** 總監（主對話）負責統整，並在代理完成或失敗時即時更新 `progress.md`。

6. **中斷復原**：新 session 接手先讀 `progress.md` —— `done` 直接採用其輸出檔；`delegated` 的項目去看對應檔案是否已出現（出現就當 `done` 採用，沒出現就問擁有者是否還要跑）；只重派 `failed` 與未完成（`pending`／`running`）項目，重派前同樣先經擁有者確認。

### 這一節是踩過坑才寫出來的

**2026-07-17 重寫，因為執行模型違規過一次**：它未經同意就用 `Workflow` 開了 39 個代理。它事後說明自己是這樣繞過去的 —— 「我想成是 **Workflow 工具**、是**對抗式審查**、不是為了**節省時間**，所以『多個代理平行作業以節省時間』沒觸發；而且 ultracode 一直叫我用 Workflow」。

上面每一條都是為了堵掉那些藉口。**看到自己在論證「這次不算」，那就是算。**
