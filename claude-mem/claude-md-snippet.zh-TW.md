## claude-mem —— 它是什麼，以及它不是什麼

`claude-mem` 會被動記錄這個 session 的觀察，並在之後的 session 開始時注入相關內容。你不需要操作它，是它在觀察你。

### 它不是專案的 `Memory/` 資料夾，而這個差別是關鍵

| | claude-mem | 專案的 `Memory/` 資料夾 |
|---|---|---|
| 放在哪 | `~/.claude-mem`，本機的 SQLite 資料庫 | repo 裡的檔案 |
| 誰讀得到 | **只有這台機器、只有這個帳號** | 每一個 clone 這個 repo 的人 |
| 換新工作站還在嗎 | **不在** | 在，它在 git 裡 |
| 能在 diff 裡被審查嗎 | 不能 | 能 |
| 誰寫的 | hook，自動 | 你，刻意地 |

**待辦事項、決策、交接、以及任何「別人要照著做」的東西，一律寫進檔案。** claude-mem「記得」它，不能滿足任何要求書面記錄的規則 —— 下一個人、下一台機器、審查的人，通通看不到。如果你的專案指示指名了待辦檔、任務資料夾或決策記錄，那些仍然是這些東西唯一該待的地方。

claude-mem 拿來做它擅長的事：***「這個我以前是不是遇過？」***

### 四種看起來像故障、其實不是的行為

1. **全新專案的第一個 session 不會有注入的記憶。** 注入從**第二個** session 才開始，因為第一個 session 正是產生那些觀察的人。
2. **觀察會自己出現，不需要你要求。** 它在 agent 讀檔、改檔、跑指令的過程中持續串流進去。**永遠不要宣稱你「把這個存進 claude-mem 了」** —— 沒有任何東西是被你存進去的，這樣講等於發明了一個沒有發生的動作。
3. **worker 沒在跑的時候，什麼都不會被記錄。** 它是本機服務，port 37777。`npx claude-mem status` 一行回答你；`npx claude-mem doctor` 做診斷。
4. **隊友的 session 看不到你的觀察，你的也看不到他的。** 資料庫是每台機器、每個帳號各自獨立的。除非你另外買了同步，否則沒有同步。

### 怎麼搜尋

在重做別人（或上個月的你）已經完成的工作之前，先搜：

```
npx claude-mem search "<你正要開始做的事>"
```

如果這個 session 有 `mem-search` skill，優先用它 —— 同一個資料庫，介面比較好。**搜不到不等於不存在**：記憶裡只有「在這台機器上、而且 worker 有在跑」的那些 session。搜不到要當成 UNCONFIRMED，回去查 repo 本身，再下「沒有人做過」的結論。
